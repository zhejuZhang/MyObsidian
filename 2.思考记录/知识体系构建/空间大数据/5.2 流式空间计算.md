# 流式空间计算

> 流式空间计算是实时处理持续到达的空间数据流的计算范式，适用于实时交通监控、位置追踪、灾害预警等场景。

---

## 概述

### 流处理 vs 批处理

| 特性 | 批处理 | 流处理 |
|------|--------|--------|
| 数据 | 有界数据集 | 无界数据流 |
| 延迟 | 分钟~小时 | 毫秒~秒 |
| 吞吐量 | 高 | 中~高 |
| 语义 | 精确一次 | 至少一次/精确一次 |
| 典型框架 | Spark Batch | Flink, Kafka Streams |

### 空间流数据特征

```
空间流数据 = 时间序列 + 空间位置

{
  "stream_id": "vehicle_001",
  "timestamp": 1704067200000,
  "longitude": 116.397,
  "latitude": 39.908,
  "speed": 45.2,
  "heading": 180
}

挑战:
- 数据持续到达，无法全部存储
- 需要实时处理和响应
- 空间计算复杂度高
- 时间窗口内的空间分析
```

## 流处理核心概念

### 时间语义

```
事件时间 (Event Time): 事件实际发生的时间
摄入时间 (Ingestion Time): 事件进入系统的时间
处理时间 (Processing Time): 事件被处理的时间

对于空间数据，通常使用事件时间:
- GPS 轨迹的采集时间
- 传感器的观测时间
```

### 窗口（Window）

```
滚动窗口 (Tumbling Window):
|---W1---|---W2---|---W3---|
固定大小，不重叠

滑动窗口 (Sliding Window):
|---W1---|
   |---W2---|
      |---W3---|
固定大小，有重叠

会话窗口 (Session Window):
|--W1--|   |---W2---|
基于活动间隔，大小不固定

全局窗口 (Global Window):
|----------所有数据----------|
需要自定义触发器
```

### 水位线（Watermark）

```
水位线 = 已处理的最大事件时间 - 允许延迟

作用:
- 标识事件时间的进度
- 决定窗口何时关闭
- 处理乱序数据

空间数据中的水位线:
- GPS 数据可能乱序到达
- 需要设置合理的延迟容忍
```

## Flink 流式空间计算

### 空间数据流处理

```java
// 从 Kafka 读取 GPS 轨迹流
DataStream<GpsPoint> gpsStream = env
    .addSource(new FlinkKafkaConsumer<>("gps-topic", new GpsSchema(), properties))
    .assignTimestampsAndWatermarks(
        WatermarkStrategy.<GpsPoint>forBoundedOutOfOrderness(Duration.ofSeconds(5))
            .withTimestampAssigner((event, timestamp) -> event.getTimestamp())
    );

// 空间过滤: 匹配地理围栏
DataStream<GpsPoint> filtered = gpsStream
    .filter(new SpatialFilter(geofencePolygon));

// 空间聚合: 按网格统计
DataStream<GridCount> aggregated = gpsStream
    .keyBy(point -> H3.geoToH3Address(point.getLat(), point.getLng(), 9))
    .window(TumblingEventTimeWindows.of(Time.minutes(5)))
    .aggregate(new CountAggregator());
```

### 实时空间连接

```java
// 实时轨迹与地理围栏的连接
DataStream<Alert> alerts = gpsStream
    .keyBy(GpsPoint::getVehicleId)
    .connect(geofenceStream)
    .process(new SpatialJoinProcessFunction());

// ProcessFunction 中的实现
public class SpatialJoinProcessFunction 
    extends KeyedCoProcessFunction<String, GpsPoint, Geofence, Alert> {
    
    // 维护地理围栏状态
    private ValueState<Geofence> geofenceState;
    
    @Override
    public void processElement1(GpsPoint point, Context ctx, Collector<Alert> out) {
        Geofence fence = geofenceState.value();
        if (fence != null && fence.contains(point)) {
            out.collect(new Alert(point, fence));
        }
    }
}
```

### 状态管理

```
空间流处理中的状态:
- 地理围栏集合: 需要高效的空间查询
- 轨迹历史: 滑动窗口内的轨迹点
- 聚合状态: 网格/区域的统计信息

状态后端:
- MemoryStateBackend: 小规模，开发测试
- FsStateBackend: 大规模，持久化到文件系统
- RocksDBStateBackend: 超大规模，使用 RocksDB
```

## Kafka Streams 空间处理

```java
// Kafka Streams 空间处理
StreamsBuilder builder = new StreamsBuilder();

KStream<String, GpsPoint> gpsStream = builder.stream("gps-topic");

// 空间过滤
KStream<String, GpsPoint> inCity = gpsStream
    .filter((key, point) -> cityBoundary.contains(point));

// 空间聚合 (按网格)
KTable<Windowed<String>, Long> gridCounts = inCity
    .groupBy((key, point) -> GeoHash.encode(point.getLat(), point.getLng(), 6))
    .windowedBy(TimeWindows.ofSizeWithNoGrace(Duration.ofMinutes(5)))
    .count();

// 输出结果
gridCounts.toStream().to("grid-counts-topic");
```

## 空间流处理模式

### 实时地理围栏

```
输入: GPS 轨迹流
处理:
  1. 查询轨迹点是否在围栏内
  2. 检测进入/离开事件
  3. 生成告警

输出: 围栏事件流 (进入/离开/停留)

应用:
- 车辆监控
- 人员管理
- 物流追踪
```

### 实时热点检测

```
输入: 事件位置流
处理:
  1. 按空间网格聚合
  2. 滑动窗口内统计
  3. 检测异常高密度区域

输出: 热点区域流

应用:
- 突发事件检测
- 交通拥堵预警
- 疫情监控
```

### 实时轨迹分析

```
输入: 移动对象轨迹流
处理:
  1. 轨迹分段
  2. 停留点检测
  3. 异常行为识别

输出: 轨迹语义流

应用:
- 出行模式分析
- 异常行为检测
- 路径推荐
```

### 实时空间聚合

```
输入: 空间事件流
处理:
  1. 按区域/网格聚合
  2. 时间窗口内统计
  3. 趋势检测

输出: 空间统计流

应用:
- 实时交通流量统计
- 区域人流热力图
- 环境监测
```

## 窗口空间计算

### 滑动窗口空间聚类

```
窗口: 最近 10 分钟，每 1 分钟滑动

每个窗口内:
1. 收集窗口内的所有轨迹点
2. 执行 DBSCAN 聚类
3. 输出聚类结果

挑战:
- 窗口数据量大
- 需要增量计算
- 聚类结果的连续性
```

### 会话窗口轨迹分段

```
会话间隔: 30 分钟无新点则结束会话

每个会话:
1. 轨迹点序列
2. 可以进行轨迹分析
3. 检测停留点和移动段
```

## 性能优化

### 空间索引的流式维护

```
维护滑动窗口的空间索引:
- 新数据到达: 插入索引
- 数据过期: 从索引中删除
- 使用支持删除的索引结构

方案:
- 松散四叉树 (Loose Quadtree)
- 时间分区的 R-tree
- 增量更新的网格索引
```

### 状态压缩

```
空间状态的压缩:
- 轨迹压缩: Douglas-Peucker 算法
- 空间聚合: 用网格代替精确位置
- 过期清理: 及时清理过期状态
```

### 并行度调优

```
并行度设置:
- Source 并行度: 匹配 Kafka 分区数
- 处理并行度: 根据计算复杂度调整
- Sink 并行度: 匹配下游消费能力

空间数据的特殊考虑:
- 按空间分区 keyBy
- 避免数据倾斜
- 合理设置水位线延迟
```
