# 分布式计算原理

> 分布式计算是将大规模计算任务分解到多台计算机上并行执行的计算范式，是大数据处理的理论基础。

---

## 分布式系统基础

### 定义

分布式系统是由多台通过网络连接的计算机组成的系统，对外表现为一个统一的整体。

### 核心挑战

- **网络不可靠**：消息可能丢失、延迟、乱序
- **时钟不同步**：各节点的本地时钟存在偏差
- **节点可能故障**：任何节点都可能随时失效
- **并发控制**：多节点同时访问共享资源

---

## CAP 理论

分布式系统的三个基本属性不可能同时满足：

```
        Consistency (一致性)
           /\
          /  \
         /    \
        / CAP  \
       /________\
Availability    Partition
 (可用性)      Tolerance (分区容错)
```

| 属性 | 含义 |
|------|------|
| **一致性（C）** | 所有节点看到相同的数据 |
| **可用性（A）** | 每个请求都能得到响应 |
| **分区容错（P）** | 网络分区时系统仍能运行 |

### 取舍

- **CP 系统**：放弃可用性，保证一致性（如 ZooKeeper、HBase）
- **AP 系统**：放弃一致性，保证可用性（如 Cassandra、DynamoDB）
- **CA 系统**：无网络分区时可同时满足（如传统关系数据库）

---

## 一致性模型

### 强一致性

```
写操作完成后，所有后续读操作都能看到最新值
实现成本高，性能差
```

### 最终一致性

```
写操作完成后，经过一段时间后所有节点达到一致
实现成本低，性能好
大多数分布式系统采用此模型
```

### 因果一致性

```
保证有因果关系的操作顺序一致
无因果关系的操作可以不一致
```

## 分布式架构模式

### 主从架构（Master-Slave）

```
┌──────────┐
│  Master  │ ← 负责协调和元数据管理
└────┬─────┘
     │
┌────┴────┬──────────┐
│         │          │
▼         ▼          ▼
Slave₁   Slave₂   Slave₃  ← 负责数据存储和计算
```

- 优点：架构简单，易于管理
- 缺点：Master 是单点故障

### 对等架构（Peer-to-Peer）

```
┌─────┐     ┌─────┐
│Node₁│ ←→ │Node₂│
└──┬──┘     └──┬──┘
   │           │
   └───┐ ┌───┘
       ▼ ▼
     ┌─────┐
     │Node₃│
     └─────┘
```

- 优点：无单点故障，可扩展性好
- 缺点：协调复杂

### 分片架构（Sharding）

```
数据按某种规则分散到不同节点:

Shard₁: key ∈ [0, 100)
Shard₂: key ∈ [100, 200)
Shard₃: key ∈ [200, 300)
```

## 容错机制

### 数据复制（Replication）

```
每个数据块保存多个副本:
Block₁ → [Node₁, Node₃, Node₅]
Block₂ → [Node₂, Node₄, Node₆]

副本策略:
- 同机架复制: 低延迟，但机架故障会丢失所有副本
- 跨机架复制: 高可靠性，但网络开销大
```

### 故障检测

```
心跳机制:
Node₁ ──heartbeat──→ Node₂
如果在超时时间内未收到心跳，则判定节点故障

超时时间设置:
- 太短: 误判率高
- 太长: 故障恢复慢
```

### 故障恢复

```
1. 检测到节点故障
2. 从其他副本恢复数据
3. 重新分配任务
4. 维持副本数量
```

## 分布式计算模型

### MapReduce

```
Map: (key₁, value₁) → [(key₂, value₂)]
Shuffle: 按 key 分组
Reduce: (key₂, [value₂]) → [(key₃, value₃)]
```

### BSP（Bulk Synchronous Parallel）

```
超级步（Superstep）:
1. 本地计算
2. 消息传递
3. 同步屏障

适用于图计算（如 Pregel、Giraph）
```

### DAG（Directed Acyclic Graph）

```
将计算任务表示为有向无环图:
Task₁ → Task₂ → Task₃
             ↘ Task₄

Spark 的核心计算模型
```
