# 分布式空间存储

> 分布式空间存储解决海量空间数据在多节点上的组织和管理问题，核心挑战是保持空间局部性的同时实现负载均衡。

---

## 核心挑战

### 空间数据分区的困难

传统数据分区（Hash、Range）会破坏空间局部性：
```
Hash 分区:
  空间邻近的数据被分散到不同节点
  → 空间查询需要访问所有节点

Range 分区:
  按某一维排序分区
  → 数据分布不均，热点问题
```

空间分区的目标：
- **空间局部性**：邻近数据在同一节点
- **负载均衡**：各节点数据量相近
- **最小化跨节点查询**

---

## 空间分区策略

### 规则网格分区

```
将空间划分为均匀网格，每个网格对应一个分区:

┌───┬───┬───┬───┐
│ P1│ P2│ P3│ P4│
├───┼───┼───┼───┤
│ P5│ P6│ P7│ P8│
├───┼───┼───┼───┤
│ P9│P10│P11│P12│
└───┴───┴───┴───┘

优点: 实现简单，查询路由快速
缺点: 数据分布不均时负载不均衡
```

### 四叉树分区

```
递归地将空间四等分，直到每个分区的数据量达到阈值:

        ┌───────┬───────┐
        │       │       │
        │   ┌───┤       │
        │   │ ● │       │
        ├───┼───┤       │
        │   │ ● │       │
        │   └───┤       │
        │       │       │
        └───────┴───────┘

优点: 自适应数据分布
缺点: 分区边界不规则
```

### R-tree 分区

```
使用 R-tree 的 MBR 作为分区边界:
- 每个 R-tree 节点对应一个存储分区
- 分区边界由数据的 MBR 决定
- 支持动态调整
```

### 空间填充曲线分区

```
使用 Hilbert 曲线或 Z-order 曲线将二维空间映射到一维:

Hilbert 曲线:
┌──┬──┐
│  ↓  │
├──→──┤
│  ↑  │
└──┴──┘

然后按一维顺序分区:
- 保持空间局部性
- 可使用传统的一维分区方法
- 广泛用于分布式空间数据库
```

## HDFS 上的空间存储

### 空间文件格式

**GeoTIFF**：
```
结构: TIFF + 地理元数据
特点: 自包含，支持 COG (Cloud Optimized GeoTIFF)
COG 优化: 支持 HTTP Range 请求，按需读取
```

**Parquet + WKB/WKT**：
```
结构: 列式存储 + 几何列 (WKB/WKT)
特点: 列裁剪，压缩率高
适合: 大规模矢量数据分析
```

**ORC**：
```
结构: 列式存储 + 空间列
特点: 索引丰富，ACID 支持
适合: Hive 生态
```

### 空间数据在 HDFS 上的组织

```
按空间分区组织:
/user/data/spatial/
├── region=00/  (Hilbert 分区 0)
│   ├── part-00000.parquet
│   └── part-00001.parquet
├── region=01/  (Hilbert 分区 1)
│   └── part-00000.parquet
...

按时间+空间分区:
/user/data/trajectories/
├── year=2024/month=01/space=00/
├── year=2024/month=01/space=01/
...
```

## HBase 上的空间存储

### 空间数据的 Row Key 设计

**GeoHash 编码**：
```
Row Key = GeoHash + Timestamp + ID

示例:
"wx4g09_20240101_001"
"wx4g09_20240101_002"

优点: 空间邻近的数据在 HBase 中也相邻
缺点: 边界查询需要扫描多个 GeoHash 前缀
```

**H3 索引**：
```
Row Key = H3 Index + Timestamp

优点: 六边形网格无边界问题
缺点: 精度受 H3 分辨率限制
```

### 空间查询的实现

```
范围查询:
1. 计算查询窗口覆盖的 GeoHash/H3 单元
2. 对每个单元发起 HBase Scan
3. 合并结果

最近邻查询:
1. 从候选点所在单元开始
2. 逐步扩展到相邻单元
3. 直到找到 K 个最近邻
```

## 分布式空间索引

### 全局索引 vs 局部索引

```
全局索引:
- 一个索引覆盖所有节点
- 查询只需访问一个索引
- 更新开销大，单点瓶颈

局部索引:
- 每个节点维护自己的索引
- 查询需要访问所有节点的索引
- 更新简单，并行性好
```

### 常见方案

**GeoMesa 的分布式索引**：
```
Z2 索引: 二维点数据的 Z-order 索引
XZ2 索引: 二维范围数据的 XZ-order 索引
S2 索引: 基于 S2 几何的索引
Attribute 索引: 属性+空间的联合索引
```

**SpatialHadoop**：
```
- 在 Hadoop 上实现的空间索引
- 支持 R-tree、Quad-tree、Grid 等
- 全局索引 + 局部索引
- MapReduce 空间查询
```

## 数据格式与序列化

### GeoJSON

```json
{
  "type": "Feature",
  "geometry": {
    "type": "Point",
    "coordinates": [116.397, 39.908]
  },
  "properties": {
    "name": "天安门"
  }
}
```
- 人类可读
- 冗余大，不适合大数据

### WKB（Well-Known Binary）

```
二进制格式，紧凑高效:
- 几何类型 (4 bytes)
- 坐标数据 (N bytes)

适合: 大数据存储和传输
```

### FlatGeobuf

```
特点:
- 二进制格式
- 内置空间索引 (R-tree)
- 支持流式读取
- 适合 Web 传输
```
