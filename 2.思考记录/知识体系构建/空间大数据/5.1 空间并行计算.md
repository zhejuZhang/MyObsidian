# 空间并行计算

> 空间并行计算是将空间计算任务分配到多个处理器或节点上同时执行的计算范式，是处理空间大数据的核心技术。

---

## 概述

空间计算的特点使其并行化面临独特挑战：
- **数据局部性**：空间操作需要访问特定区域的数据
- **负载不均**：空间数据分布不均匀
- **通信开销**：空间连接等操作需要大量数据交换
- **边界问题**：分区边界处的数据需要特殊处理

---

## MapReduce 空间计算

### 基本范式

```
空间 MapReduce:

Map 阶段:
  输入: 空间数据分片
  处理: 对每个空间对象执行局部计算
  输出: (partition_key, spatial_object)

Shuffle 阶段:
  按 partition_key 分组，将数据路由到对应的 Reducer

Reduce 阶段:
  输入: 同一分区的空间对象集合
  处理: 执行需要全局信息的空间计算
  输出: 计算结果
```

### 空间范围查询

```python
# Map 阶段
def map(record):
    geom, properties = record
    if geom.intersects(query_window):
        emit(key=partition_id, value=(geom, properties))

# Reduce 阶段
def reduce(key, values):
    for geom, properties in values:
        if geom.within(query_window):
            emit(result=(geom, properties))
```

### 空间连接（Spatial Join）

```
问题: 找出两个数据集中空间相交的对象对

R-tree 空间连接:
1. Map 阶段:
   - 对数据集 A 和 B 分别建立局部 R-tree
   - 用查询窗口的 MBR 初步筛选
2. Reduce 阶段:
   - 对候选对执行精确的空间关系判断

空间分区连接:
1. 用统一的空间分区对两个数据集重分区
2. 同一分区内的数据进行局部空间连接
3. 处理边界对象（可能属于多个分区）
```

### SpatialHadoop

在 Hadoop 上实现的空间计算框架：

```
组件:
- 空间文件格式: SpatialFile
- 全局索引: 跨节点的空间索引
- 局部索引: 每个节点的本地索引
- 空间操作: Range Query, KNN, Spatial Join

优化:
- 索引感知的数据分片
- 空间感知的作业调度
- 避免不必要的数据传输
```

## Spark 空间计算

### Apache Sedona（原 GeoSpark）

Spark 原生的空间计算扩展：

```python
from sedona.spark import SedonaContext

sedona = SedonaContext.builder().getOrCreate()

# 读取空间数据
points = sedona.read.format("csv") \
    .option("delimiter", "\t") \
    .load("hdfs:///data/points.tsv") \
    .withColumn("geom", ST_Point(col("lon"), col("lat")))

# 空间范围查询
result = points.filter(
    ST_Within(col("geom"), ST_GeomFromWKT("POLYGON((...))"))
)

# 空间连接
joined = points.join(polygons,
    ST_Within(points.geom, polygons.geom)
)

# 空间聚合
result = points.groupBy(
    ST_GeoHash(col("geom"), 5).alias("geohash")
).count()
```

### Sedona 的核心优化

**空间分区**：
```
支持的分区策略:
- SpatialPartitioning: 基于空间位置的分区
- QuadTreePartitioning: 四叉树分区
- KDBTreePartitioning: K-D-B 树分区
- H3Partitioning: H3 六边形分区

分区后:
- 空间邻近的数据在同一分区
- 空间查询只需访问相关分区
- 减少 Shuffle 数据量
```

**空间索引**：
```
每个分区建立局部索引:
- R-tree 索引
- Quad-tree 索引

查询时:
1. 通过分区键定位相关分区
2. 在分区内通过索引快速检索
3. 执行精确的空间关系判断
```

### Spark DataFrame 空间操作

```sql
-- 使用 Spark SQL 进行空间查询
SELECT a.name, b.district
FROM points a, polygons b
WHERE ST_Within(a.geom, b.geom);

-- 空间聚合
SELECT ST_GeoHash(geom, 6) AS geohash, COUNT(*) AS cnt
FROM points
GROUP BY ST_GeoHash(geom, 6);

-- 最近邻查询
SELECT a.name, b.name AS nearest
FROM points a
JOIN LATERAL (
    SELECT name
    FROM points b
    WHERE a.id != b.id
    ORDER BY ST_Distance(a.geom, b.geom)
    LIMIT 1
) b ON true;
```

## Flink 空间计算

### Apache Flink 的空间支持

```java
// 注册空间 UDF
TableEnv.createTemporaryFunction("ST_Point", new ST_Point());
TableEnv.createTemporaryFunction("ST_Within", new ST_Within());

// 流式空间查询
Table result = tableEnv.sqlQuery(
    "SELECT * FROM points " +
    "WHERE ST_Within(geom, ST_GeomFromWKT('POLYGON((...))'))"
);

// 流式空间连接
Table joined = tableEnv.sqlQuery(
    "SELECT a.id, b.zone_name " +
    "FROM points a JOIN zones b " +
    "ON ST_Within(a.geom, b.geom)"
);
```

## 并行空间算法设计

### 并行空间聚类

```
DBSCAN 并行化:

1. 数据分区: 空间分区，每个分区包含局部数据
2. 局部聚类: 每个分区独立执行 DBSCAN
3. 合并: 处理分区边界的聚类合并
   - 边界点的邻域可能跨分区
   - 需要通信来合并跨分区的簇
```

### 并行空间连接

```
两阶段空间连接:

阶段 1: 参与者过滤
- 对两个数据集分别建立空间索引
- 用 MBR 过滤不相交的候选对

阶段 2: 精确验证
- 对候选对执行精确几何计算
- 输出满足空间关系的对象对

优化:
- 分区端复制连接 (Partition-level Replicated Join)
  小数据集广播到所有节点
- 分区端重划分连接 (Partition-level Repartition Join)
  两个数据集按相同策略重分区
```

### 并行 KNN 查询

```
1. 查询分发: 将查询点广播到所有分区
2. 局部 KNN: 每个分区找到局部 K 个最近邻
3. 全局合并: 合并所有分区的结果，取全局 K 个最近邻
4. 验证: 确保没有遗漏更近的点（需要考虑边界）
```

## 性能优化

### 数据本地性

```
将计算调度到数据所在的节点:
- 减少网络传输
- 利用本地索引
- Spark 的 preferred locations
```

### 索引复用

```
在多个查询之间复用空间索引:
- 缓存索引到内存
- 避免重复建索引的开销
- Sedona 支持索引持久化
```

### 谓词下推

```
将空间过滤条件下推到数据源:
- 在读取数据时就进行空间过滤
- 减少需要处理的数据量
- Parquet 的空间过滤下推
```
