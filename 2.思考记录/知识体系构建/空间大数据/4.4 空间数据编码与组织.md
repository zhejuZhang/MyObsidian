# 空间数据编码与组织

> 空间数据的编码和组织方式直接影响存储效率、查询性能和计算效率。

---

## 几何编码

### WKT（Well-Known Text）

文本格式的几何表示：

```
POINT (116.397 39.908)
LINESTRING (0 0, 1 1, 2 2)
POLYGON ((0 0, 1 0, 1 1, 0 1, 0 0))
MULTIPOINT ((0 0), (1 1))
MULTILINESTRING ((0 0, 1 1), (2 2, 3 3))
MULTIPOLYGON (((0 0, 1 0, 1 1, 0 1, 0 0)))
GEOMETRYCOLLECTION (POINT (0 0), LINESTRING (0 0, 1 1))
```

### WKB（Well-Known Binary）

二进制格式，更紧凑：

```
结构:
[字节序 (1B)] [几何类型 (4B)] [坐标数据 (NB)]

字节序: 0=大端, 1=小端
几何类型:
  1=Point, 2=LineString, 3=Polygon
  4=MultiPoint, 5=MultiLineString, 6=MultiPolygon
  7=GeometryCollection
```

### GeoJSON

JSON 格式的几何表示，见 [[4.3 分布式空间存储]]。

### MVT（Mapbox Vector Tiles）

矢量瓦片格式：

```
将空间数据按瓦片金字塔切分:
- 每个瓦片是 Protobuf 编码的矢量数据
- 支持多分辨率
- 压缩率高
- 适合 Web 地图渲染

瓦片坐标: z/x/y
  z: 缩放级别 (0-22)
  x: 列号
  y: 行号
```

## 栅格编码

### 原始编码

```
逐像素存储:
- BSQ (Band Sequential): 按波段顺序存储
- BIP (Band Interleaved by Pixel): 按像素交错
- BIL (Band Interleaved by Line): 按行交错
```

### 压缩编码

| 编码 | 类型 | 特点 |
|------|------|------|
| LZW | 无损 | 通用，压缩率中等 |
| DEFLATE | 无损 | 压缩率高，速度慢 |
| JPEG | 有损 | 压缩率高，不适合分析 |
| JPEG2000 | 有损/无损 | 支持渐进式传输 |
| CCITT | 无损 | 适合二值图像 |

### COG（Cloud Optimized GeoTIFF）

云优化的 GeoTIFF：

```
特点:
- 内置概览（Overview/Pyramid）
- 数据按条带（Strip）或瓦片（Tile）组织
- 支持 HTTP Range 请求
- 可按需读取任意区域

结构:
┌─────────────────┐
│   Overview 1/4  │  ← 最粗分辨率
├────────┬────────┤
│   O2   │   O2   │  ← 中等分辨率
├───┬────┼───┬────┤
│ O3│ O3 │ O3│ O3 │  ← 原始分辨率
└───┴────┴───┴────┘
```

### NetCDF/HDF5

科学数据格式：

```
NetCDF (Network Common Data Form):
- 自描述格式
- 支持多维数组
- 广泛用于气象、海洋数据

HDF5 (Hierarchical Data Format):
- 层次化数据组织
- 支持超大规模数据
- NASA 地球观测数据标准格式
```

## 空间数据分区

### 空间分区策略

**规则网格分区**：
```
按固定大小的网格划分空间:
┌───┬───┬───┬───┐
│ 0 │ 1 │ 2 │ 3 │
├───┼───┼───┼───┤
│ 4 │ 5 │ 6 │ 7 │
└───┴───┴───┴───┘

分区键 = grid_id
查询时先定位网格，再查询网格内的数据
```

**空间填充曲线分区**：
```
Z-order (Morton) 曲线:
将二维坐标编码为一维:
(x, y) → interleaving(x, y)

示例:
(3, 5) = (011, 101) → 011011 = 27

Hilbert 曲线:
更好的空间局部性
编码更复杂
```

**自适应分区**：
```
基于数据分布的分区:
- 四叉树分区
- R-tree 分区
- K-D Tree 分区

目标: 每个分区的数据量均衡
```

### 分区键选择

| 分区策略 | 适用场景 | 优缺点 |
|----------|----------|--------|
| 空间网格 | 均匀分布数据 | 简单但可能不均衡 |
| GeoHash | 通用 | 前缀查询高效，边界问题 |
| H3 | 区域聚合 | 六边形无边界问题 |
| Hilbert | 大规模数据 | 局部性最好，计算复杂 |

## 数据压缩

### 几何压缩

**坐标压缩**：
```
Delta 编码:
  原始: (100, 200), (102, 203), (105, 207)
  Delta: (100, 200), (+2, +3), (+3, +4)
  → 小数值压缩率更高

整数化:
  将浮点坐标转换为整数:
  116.397 → 116397000 (保留 6 位小数)
  → 可用 Varint 编码进一步压缩
```

**拓扑压缩**：
```
存储共享边和节点，避免重复:
- 面实体共享边界
- 节点只存储一次
- 典型: TopoJSON
```

### 栅格压缩

```
分块压缩:
- 将栅格分成小块 (如 256×256)
- 每块独立压缩
- 支持按需解压

预测编码:
- 差分脉冲编码调制 (DPCM)
- 利用相邻像素的相似性
```

## 空间数据索引编码

### GeoHash 编码

```
Base32 字符集: 0123456789bcdefghjkmnpqrstuvwxyz

精度对应:
长度 1: 5000 km
长度 2: 1250 km
长度 3: 156 km
长度 4: 39 km
长度 5: 5 km
长度 6: 1.2 km
长度 7: 152 m
长度 8: 38 m
```

### H3 编码

```
64 位整数编码:
[模式 (4位)] [保留 (3位)] [分辨率 (4位)] [单元格 (45位)+方向位]

分辨率 0-15，共 16 级
```

### S2 编码

```
64 位整数:
- 3 位面 ID (立方体的 6 个面)
- 每级 2 位 (4 个子单元)
- 最多 30 级
```
