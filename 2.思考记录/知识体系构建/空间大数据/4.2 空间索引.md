# 空间索引

> 空间索引是加速空间查询的数据结构，通过组织空间数据的空间分布，避免全表扫描，是空间数据库性能的关键。

---

## 概述

空间查询（范围查询、最近邻查询、空间连接）如果不使用索引，需要逐条计算空间关系，时间复杂度 O(N²)。空间索引通过层次化的空间划分，将查询复杂度降低到 O(log N)。

---

## R-tree 家族

### R-tree

最基本的空间索引结构：

```
结构:
- 叶节点: 包含实际几何对象的 MBR (最小外接矩形)
- 非叶节点: 包含子节点 MBR 的 MBR
- 根节点: 包含所有数据的 MBR

        ┌─────────────┐
        │  Root MBR   │
        └──────┬──────┘
       ┌───────┴───────┐
  ┌────┴────┐    ┌─────┴────┐
  │ Node₁   │    │ Node₂    │
  │ MBR     │    │ MBR      │
  └────┬────┘    └─────┬────┘
   ┌───┴───┐      ┌───┴───┐
   │Obj│Obj│      │Obj│Obj│
   └───┴───┘      └───┴───┘
```

**查询过程**（范围查询）：
```
1. 从根节点开始
2. 检查子节点 MBR 是否与查询窗口相交
3. 相交则递归进入该子节点
4. 到达叶节点时，精确判断对象是否在窗口内
```

### R*-tree

R-tree 的优化版本：
- **强制重插入**：插入时如果节点溢出，先移除部分条目再重新插入
- **更好的分裂策略**：选择分裂轴和分裂点的启发式方法
- **性能提升**：查询性能比 R-tree 提高 10%-50%

### R+-tree

允许节点重叠的变体：
- 一个对象可能出现在多个叶节点中
- 查询时不需要回溯
- 空间利用率更高，但存储开销增大

### Bulk Loading

大规模数据的批量建索引：
```
STR (Sort-Tile-Recursive) 算法:
1. 按 X 坐标排序
2. 分成 √(N/M) 个条带
3. 每个条带内按 Y 坐标排序
4. 每 M 个对象形成一个叶节点
5. 自底向上构建树
```

## 四叉树（Quad-tree）

### 原理

将空间递归地四等分：

```
┌───────┬───────┐
│       │       │
│ NW    │ NE    │
│       │       │
├───────┼───────┤
│       │       │
│ SW    │ SE    │
│       │       │
└───────┴───────┘

每个象限可继续四分，直到满足停止条件
（如：节点内对象数 < 阈值）
```

### 变体

- **点四叉树**：存储点对象
- **区域四叉树**：存储面对象
- **MX 四叉树**：固定深度，类似 Morton 编码
- **松散四叉树**：节点边界有弹性，减少更新开销

### 优缺点

| 优点 | 缺点 |
|------|------|
| 结构简单 | 深度不均衡 |
| 实现容易 | 边界对象处理复杂 |
| 适合点数据 | 面数据效率低 |
| 支持动态更新 | 存储空间可能浪费 |

## 网格索引（Grid Index）

### 原理

将空间划分为均匀网格：

```
┌───┬───┬───┬───┐
│   │ ● │   │   │  ● 表示对象
├───┼───┼───┼───┤
│   │   │ ● │   │
├───┼───┼───┼───┤
│ ● │   │   │ ● │
├───┼───┼───┼───┤
│   │   │ ● │   │
└───┴───┴───┴───┘

每个网格单元记录落入其中的对象列表
```

### 多级网格

```
Level 1: 粗网格 → 快速定位大致区域
Level 2: 中等网格 → 缩小范围
Level 3: 细网格 → 精确定位
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 实现极简 | 数据分布不均时效率低 |
| 查询速度快 | 网格大小难以选择 |
| 内存友好 | 跨网格对象处理复杂 |

## 空间哈希

### GeoHash

将二维坐标编码为一维字符串：

```
编码过程:
1. 将经纬度范围递归二分
2. 经度在左半部分记 0，右半部分记 1
3. 纬度在左半部分记 0，右半部分记 1
4. 交替进行经度和纬度的二分
5. 将二进制串转换为 Base32 字符串

示例:
北京 (116.407, 39.908) → "wx4g09v"

特性:
- 前缀相同的字符串在空间上邻近
- 字符串越长，精度越高
- 支持前缀范围查询
```

### S2 Geometry

Google 开发的球面几何库：
- 将球面投影到立方体的六个面
- 使用 Hilbert 曲线填充每个面
- 单元格 ID 是 64 位整数
- 支持多分辨率

### H3

Uber 开发的六边形网格系统：

```
特点:
- 全球覆盖的六边形网格
- 16 级分辨率
- 面积和形状一致性好
- 支持层级关系

分辨率对应面积:
Res 0: ~4,250,546 km²
Res 5: ~252 km²
Res 9: ~0.1 km²
Res 15: ~0.000001 km²
```

## 空间索引对比

| 索引 | 类型 | 动态性 | 适用场景 |
|------|------|--------|----------|
| R-tree | 树 | 动态 | 通用空间查询 |
| R*-tree | 树 | 动态 | 高性能空间查询 |
| Quad-tree | 树 | 动态 | 点数据、多分辨率 |
| Grid | 网格 | 静态 | 均匀分布数据 |
| GeoHash | 哈希 | 动态 | 范围查询、前缀匹配 |
| S2 | 网格 | 静态 | 球面计算 |
| H3 | 网格 | 静态 | 区域聚合、分析 |

---

## 索引在大数据中的挑战

1. **数据量大**：传统索引可能无法放入内存
2. **分布式环境**：索引需要跨节点维护
3. **高更新频率**：轨迹等流式数据的索引更新
4. **多维查询**：空间+时间+属性的多维索引
