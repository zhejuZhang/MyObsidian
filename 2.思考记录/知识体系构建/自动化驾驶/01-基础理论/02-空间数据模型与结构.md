# 空间数据模型与结构

> 空间数据模型是描述和组织地理空间信息的数学框架，为自动驾驶系统提供数据组织和管理的理论基础。

---

## 一、基本概念

### 1.1 空间数据模型的定义
空间数据模型是对现实世界地理现象的抽象和数学表达，包括：
- **要素模型**：描述离散的地理实体（点、线、面）
- **场模型**描述连续变化的地理现象（温度、高程）
- **网络模型**：描述线性连接关系（道路网、管网）

### 1.2 在自动驾驶中的应用
- **高精地图**：存储车道、路沿、交通设施等空间要素
- **环境感知**：表示3D点云、语义分割结果
- **路径规划**：构建道路网络拓扑结构
- **场景理解**：组织和管理复杂的交通场景

---

## 二、矢量数据模型

### 2.1 基本要素类型

#### 点（Point）
- **定义**：零维几何对象，表示位置
- **属性**：坐标（x, y, z）、属性信息
- **应用**：交通标志、信号灯、兴趣点

#### 线（LineString）
- **定义**：一维几何对象，表示线性特征
- **存储**：有序点序列
- **应用**：车道线、道路边界、车辆轨迹

#### 面（Polygon）
- **定义**：二维几何对象，表示区域
- **存储**：闭合的环状点序列
- **应用**：可行驶区域、停车场、建筑物

### 2.2 复合几何类型

#### 多点（MultiPoint）
- **定义**：点的集合
- **应用**：离散的交通设施集合

#### 多线（MultiLineString）
- **定义**：线的集合
- **应用**：多车道道路、复杂路口

#### 多面（MultiPolygon）
- **定义**：面的集合
- **应用**：多个相连区域、复杂地理边界

### 2.3 空间关系

#### 拓扑关系
- **邻接**：两个面状要素共享边界
- **包含**：一个要素完全在另一个要素内部
- **相交**：两个要素有重叠部分
- **相离**：两个要素没有公共点

#### 方向关系
- **东、南、西、北**：基本方向
- **前、后、左、右**：相对方向
- **上、下**：垂直方向

## 三、栅格数据模型

### 3.1 基本概念
- **像元（Pixel）**：栅格数据的基本单位
- **分辨率**：像元的地面尺寸
- **波段**：数据的维度（如RGB三波段）

### 3.2 在自动驾驶中的应用

#### 语义分割图
- **定义**：每个像元标注语义类别
- **格式**：单波段整数图像
- **应用**：道路区域、可行驶区域识别

#### 占据栅格地图（Occupancy Grid Map）
- **定义**：每个像元表示占据概率
- **公式**：P(occupied) = 1 / (1 + e^(-l))
- **应用**：障碍物检测、可行驶区域判断

#### 高程模型（DEM/DSM）
- **DEM**：数字高程模型，仅地形
- **DSM**：数字表面模型，包含建筑物、植被
- **应用**：坡度分析、视域分析

### 3.3 栅格数据结构

#### 逐像元存储
- **优点**：简单直接
- **缺点**：数据量大，冗余多
- **适用**：小范围、简单场景

#### 压缩存储
- **行程编码（RLE）**：连续相同值压缩
- **四叉树**：递归分割均质区域
- **小波变换**：多分辨率压缩

## 四、三维数据模型

### 4.1 点云模型

#### 基本结构
```
Point Cloud:
  - positions: Nx3 float (x, y, z)
  - colors: Nx3 uint8 (r, g, b)
  - normals: Nx3 float (nx, ny, nz)
  - intensities: N float (反射强度)
```

#### 在自动驾驶中的应用
- **激光雷达点云**：3D环境感知
- **立体视觉点云**：视觉3D重建
- **SLAM点云**：地图构建

### 4.2 网格模型（Mesh）

#### 基本结构
- **顶点（Vertex）**：三维空间中的点
- **边（Edge）**：连接两个顶点的线段
- **面（Face）**：由边围成的多边形（通常为三角形）

#### 存储格式
- **OBJ格式**：文本格式，简单通用
- **PLY格式**：支持属性信息
- **glTF格式**：Web优化，支持压缩

### 4.3 体素模型（Voxel）

#### 基本概念
- **体素**：三维空间中的立方体单元
- **分辨率**：体素的尺寸
- **占据状态**：空闲、占据、未知

#### 应用场景
- **3D占据网格**：环境建模
- **稀疏体素**：高效存储大型场景
- **神经辐射场（NeRF）**：隐式场景表示

## 五、网络数据模型

### 5.1 道路网络模型

#### 图结构表示
```
Road Network Graph:
  Nodes: 交叉口、端点
  Edges: 路段
  Edge Attributes: 长度、车道数、限速、通行状态
```

#### 常用数据结构
- **邻接矩阵**：适合稠密网络
- **邻接表**：适合稀疏网络
- **边列表**：适合存储和传输

### 5.2 车道级网络模型

#### LaneLet2模型
- **Lanelet**：单车道段
- **Regulatory Element**：交通规则元素
- **Relation**：车道间关系

#### OpenDRIVE模型
- **Road**：道路参考线
- **Lane**：车道定义
- **Junction**：交叉口连接

### 5.3 拓扑关系

#### 连通性
- **物理连通**：实际的道路连接
- **逻辑连通**：允许的行驶路径
- **时变连通**：随时间变化的连通性

#### 方向性
- **有向图**：单向道路
- **无向图**：双向道路
- **混合图**：部分单向、部分双向

## 六、数据模型在自动驾驶中的应用

### 6.1 高精地图数据模型

#### 分层结构
```
HD Map Layers:
├── 动力学层 (Dynamic Layer)
│   ├── 交通流信息
│   ├── 交通事件
│   └── 施工区域
├── 准静态层 (Quasi-static Layer)
│   ├── 交通信号状态
│   ├── 交通标志状态
│   └── 临时障碍物
├── 静态层 (Static Layer)
│   ├── 车道几何
│   ├── 道路边界
│   ├── 交通设施
│   └── 路面标志
└── 参考层 (Reference Layer)
    ├── 道路参考线
    ├── 拓扑连接
    └── 语义关系
```

#### 属性信息
- **几何属性**：形状、位置、尺寸
- **语义属性**：类型、功能、规则
- **关系属性**：连接、邻接、包含

### 6.2 环境感知数据模型

#### 3D目标检测结果
```json
{
  "object_id": 123,
  "class": "car",
  "confidence": 0.95,
  "bbox": {
    "center": [x, y, z],
    "size": [length, width, height],
    "heading": yaw
  },
  "velocity": [vx, vy, vz]
}
```

#### 语义分割结果
- **逐像元标签**：每个像素的语义类别
- **实例标识**：区分同类别的不同实例
- **置信度图**：分类的不确定性

### 6.3 路径规划数据模型

#### 搜索空间表示
- **栅格化**：将连续空间离散化
- **采样点**：随机或确定性采样
- **路标图**：预定义的关键位置

#### 代价函数表示
- **距离代价**：路径长度
- **时间代价**：行驶时间
- **能耗代价**：能量消耗
- **安全代价**：风险评估

## 七、数据模型设计原则

### 7.1 一致性原则
- **几何一致性**：确保几何关系的正确性
- **语义一致性**：确保语义解释的一致性
- **时间一致性**：确保时间属性的一致性

### 7.2 完整性原则
- **实体完整性**：每个实体有唯一标识
- **参照完整性**：关联关系的完整性
- **域完整性**：属性值的有效性

### 7.3 效率原则
- **存储效率**：合理的数据压缩
- **查询效率**：优化的索引结构
- **计算效率**：高效的算法实现

## 九、实践建议

### 9.1 数据模型选择
1. **明确需求**：根据应用场景选择合适的数据模型
2. **考虑扩展性**：预留扩展字段和接口
3. **平衡精度与效率**：在精度和性能间取舍
4. **标准化优先**：尽量使用标准数据模型

### 9.2 常见问题与解决

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 数据冗余 | 模型设计不合理 | 规范化设计，消除冗余 |
| 查询效率低 | 缺乏索引 | 建立空间索引 |
| 数据不一致 | 缺乏约束 | 添加完整性约束 |
| 扩展困难 | 模型过于僵化 | 采用灵活的 schema-less 设计 |
